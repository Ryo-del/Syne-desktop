# Syne Desktop

Десктопный клиент Syne Cloud (только Windows). Tauri 2 + React; дизайн (`styles.css`, иконки, окна входа и файлов) взят из Syne Study. Работает как Syne для iOS: тот же Cloud API (`Syne cloud/api/openapi.yaml`), тот же вход логином и паролем (`grant_type=password`).

## Что есть

- **Вход** логином и паролем аккаунта Syne. Пароль не сохраняется; refresh-токен лежит в связке ключей ОС (Windows Credential Manager).
- **Файлы:** папки, поиск по всему облаку, загрузка (кнопка и перетаскивание из системы; чанками с докачкой, sha256), скачивание, переименование, корзина, версии с восстановлением.
- **Профиль:** аккаунт, занятое место, устройства с завершением входа.
- **Настройки:** тема, адрес сервера.

## Устройство

| Часть | Что делает |
| --- | --- |
| `src/` | Интерфейс (React). Говорит только с локальным сервисом. |
| `cmd/syne-desktop-api`, `internal/cloud` | Локальный сервис (Go, sidecar Tauri): вход, обновление токенов, проксирование `/cloud/*` в `/api/v1/*`, загрузка и скачивание. Закрыт случайным токеном запуска и проверкой Origin. |
| `src-tauri/` | Оболочка Tauri: запускает сервис и отдаёт интерфейсу токен. |

Клиент входит как `syne-windows`. Адрес сервера по умолчанию — `https://cloud.syne-network.ru`; меняется на экране входа («Сервер») или переменной `SYNE_CLOUD_SERVER`.

## Сборка

```sh
npm install
npm run tauri:dev      # сервис собирается автоматически
go test ./...          # тесты клиента облака
```

## Не сделано

- Чаты и Key Hub (устройства, шифрование, Holding): сервис должен использовать `Syne-protocol/hub` так же, как iOS (`HubService.swift`).
- Новости, просмотр и правка текста/кода, синхронизация через `/sync/changes` и WebSocket.
